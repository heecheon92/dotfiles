# Lantern

[English](README.md) | [한국어](README.ko.md)

코딩 에이전트가 계획하거나 구현하기 전에, 내가 실제로 원하는 것이
무엇인지 먼저 정확히 이해하게 만드세요.

`lantern`은 사람이 명시적으로 시작하는 독립형 요구사항 인터뷰
스킬입니다. 범위가 넓은 아이디어나 아직 구체적이지 않은 변경을 명확히
하고 싶을 때 직접 켜세요. 한 번에 하나의 질문으로 요구사항을 밝히고
실행 가능한 명세로 정리합니다. 요청이 모호하거나 복잡하거나 위험하다는
이유만으로 자동 실행되지 않습니다.

각 하네스가 제공하는 구조화 질문 인터페이스가 있으면 그것을 사용합니다.
Codex `request_user_input`, Claude Code `AskUserQuestion`, OMP `ask`,
Pi `question` 및 `questionnaire`를 지원하며, 그 외 환경에서는 번호 선택
방식으로 전환합니다.

## 바로 사용해 보기

```text
$lantern 사내 승인 절차를 바꾸고 싶습니다. 해결책을 제안하기 전에 먼저 인터뷰해 주세요.
```

Claude Code에서는 슬래시 명령으로 실행합니다.

```text
/lantern 사내 승인 절차를 바꾸고 싶습니다. 해결책을 제안하기 전에 먼저 인터뷰해 주세요.
```

기본값인 `--standard` 프로필은 명세가 준비될 때까지 충분히 질문하되,
필요 이상으로 인터뷰를 이어가지 않습니다.

더 짧거나 더 엄격한 인터뷰도 선택할 수 있습니다.

```text
$lantern --quick 이 기능의 가장 작은 유효 범위를 정의하도록 도와주세요.
```

```text
$lantern --deep 이 마이그레이션에 대해 임의로 가정하지 마세요. 의도, 범위, 위험, 완료 조건을 먼저 명확히 해주세요.
```

## 무엇을 하나요?

이 스킬은 다음 원칙으로 진행됩니다.

- 한 라운드에 핵심 질문을 정확히 하나만 합니다
- 선택지가 실제로 명확할 때는 선택형 답변을 제공합니다
- 구조화된 입력 UI가 없으면 번호 선택이나 자유 입력으로 전환합니다
- 저장소나 문서에서 확인할 수 있는 사실을 사용자에게 다시 묻지 않고
  직접 확인합니다
- 의도, 기대 결과, 범위, 제약, 성공 조건, 기존 환경을 추적합니다
- 가정, 트레이드오프, 비목표, 의사결정 경계를 드러냅니다
- 이전 답변 중 하나 이상을 다시 검토해 압박 테스트합니다
- 곧바로 구현하지 않고 검증 가능한 명세로 마무리합니다

## 어떤 식으로 진행되나요?

각 라운드에는 현재 확인 중인 항목과 추정 모호성이 표시됩니다.

```text
Round 2 | Target: Scope | Ambiguity: 34%

첫 번째 버전의 범위를 어디까지로 제한해야 하나요?

1. 소규모 파일럿 — 한 팀과 한 업무 흐름
2. 부서 단위 — 하나의 사업 부서 전체
3. 전사 도입 — 처음부터 운영 환경 전체
4. 다른 답변

번호를 선택하거나 직접 답변해 주세요.
```

현재 에이전트가 Codex이고 `request_user_input`을 사용할 수 있으면,
Lantern은 범위가 명확한 선택 질문에 Codex의 기본 구조화 질문 UI를
사용합니다. Default 모드에서는 `default_mode_request_user_input` 기능에
따라 사용 가능 여부가 달라질 수 있습니다. 사용할 수 없으면 사용자
설정을 변경하지 않고 번호 선택 형식으로 전환합니다.

Claude Code에서는 같은 선택 질문에 `AskUserQuestion`을 사용합니다. 이
도구의 헤더 필드는 12자로 제한되어 있어 라운드 표시는 질문 본문에
남기고, 직접 입력 경로는 Lantern이 만든 선택지가 아니라 Claude Code가
제공하는 `Other` 행을 사용합니다. 이 도구는 대화형 세션에서만
동작하므로 `--print` 실행이나 `dontAsk` 권한 모드에서는 번호 선택
형식으로 전환합니다.

다음 질문은 방금 한 답변을 바탕으로 결정됩니다. 미리 정해진 질문지를
기계적으로 순서대로 읽는 방식이 아닙니다.

## 프로필

```text
$lantern [--quick|--standard|--deep] <아이디어 또는 요청>
```

| 프로필 | 적합한 상황 | 모호성 목표 | 최대 라운드 |
| --- | --- | ---: | ---: |
| `--quick` | 계획 전에 빠르게 요구사항을 점검할 때 | 30% | 5 |
| `--standard` | 일반적인 요구사항 인터뷰가 필요할 때 | 20% | 12 |
| `--deep` | 위험이 크거나 매우 모호한 작업일 때 | 15% | 20 |

최대 라운드는 목표가 아니라 안전을 위한 상한입니다. 준비 조건이
충족되고 추가 질문이 실행 결과를 실질적으로 바꾸지 않으면 더 일찍
종료합니다.

## 활용하기 좋은 사례

### 모호한 기능 요청

```text
$lantern 이 애플리케이션에 팀 공유 기능을 추가하고 싶습니다. 공유의 의미를 결정하기 전에 먼저 인터뷰해 주세요.
```

### 위험한 마이그레이션

```text
$lantern --deep 기존 고객에게 영향을 주지 않고 인증 제공자를 변경해야 합니다.
```

### 새로운 사내 절차

```text
$lantern 지원 에스컬레이션 절차를 정의하고, 첫 버전에서 제외할 항목도 명확히 해주세요.
```

### 제안서 또는 발표 자료

```text
$lantern 이 제안서를 검토하고, 수정안을 제시하기 전에 청중에게서 받아야 할 결정을 명확히 해주세요.
```

## 최종 명세

인터뷰가 완료되면 필요한 항목을 골라 명세로 정리합니다.

- 의도와 기대 결과
- 포함 범위와 비목표
- 의사결정 경계
- 제약 조건
- 검증 가능한 완료 조건
- 확인 및 해결된 가정
- 기존 시스템 근거와 용어 결정
- 예외 상황과 남아 있는 위험
- 최종 모호성 점수

이 스킬은 명세를 자동으로 구현하지 않습니다. 계획, 구현, 검토 또는
명세 저장은 인터뷰가 끝난 뒤 별도로 요청할 수 있습니다.

## 설치

### Codex

Codex에 포함된 스킬 설치 도구를 사용합니다.

```bash
python3 "${CODEX_HOME:-$HOME/.codex}/skills/.system/skill-installer/scripts/install-skill-from-github.py" \
  --repo heecheon92/dotfiles \
  --path home/.agents/skills/lantern
```

설치 후 다음 Codex 턴부터 사용할 수 있습니다.

```text
$lantern --standard <주제>
```

### Claude Code

스킬 디렉터리를 개인 스킬 경로에 복사합니다.

```bash
git clone --depth 1 https://github.com/heecheon92/dotfiles.git /tmp/dotfiles
mkdir -p ~/.claude/skills
cp -R /tmp/dotfiles/home/.agents/skills/lantern ~/.claude/skills/lantern
```

특정 저장소에서만 사용하려면 그 저장소의 `.claude/skills/` 경로에
복사하세요. 설치 후 다음 턴부터 사용할 수 있습니다.

```text
/lantern --standard <주제>
```

함께 포함된 `disable-model-invocation: true` 프런트매터가 Claude의 자동
실행을 막아 주므로 그대로 두세요.

## 참고

인터뷰 상태는 현재 대화 안에서만 유지됩니다. 별도의 서비스, 터미널 UI,
상태 저장소, 보조 스크립트 또는 동반 애플리케이션이 필요하지 않습니다.

Lantern은 사람만 시작할 수 있습니다. 다른 스킬, 에이전트, 서브에이전트,
계획 또는 워크플로가 Lantern을 자동으로 실행하거나 이어서 실행해서는
안 됩니다.

선택형 UI의 표현 방식은 사용 중인 하네스 환경에 따라 달라집니다. 기본
선택 UI를 사용할 수 없는 환경에서는 같은 결정을 번호 선택과 자유 입력
형식으로 제공합니다.
